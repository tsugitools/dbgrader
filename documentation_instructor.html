DBGrader — Instructor Documentation

Author SQL exercises as JSON on a Tsugi placement, preview expected results in the browser, and grade learners by comparing SQLite outputs. Learner-facing help is in documentation.html.

Authoring an Exercise

Open Edit from the top bar (index.php?mode=author).

  1. Set Title and Prompt
  2. Choose Mode (query or database-state)
  3. Optionally set Starter SQL for the learner editor
  4. Write Solution SQL
  5. Write Setup SQL (required for query mode; optional for database-state)
  6. For database-state, add Verification SQL (semicolon-separated)
  7. Run query / Run verification preview to validate instructor SQL
  8. Save to the placement JSON
  9. View Assignment JSON — copy the exercise or a lessons.json custom snippet

Top bar

  • Learner — student view of the exercise
  • Edit — exercise authoring UI
  • Help — learner documentation
  • Instructor Help — this page
  • Student Data — grades table
  • Settings — choose a built-in assignment and due date

Always preview before publishing

Broken setup or solution SQL shows up as learner-facing failures. Use the author Run / verification preview first.

Exercise Modes

query

Compare the learner’s result set to the solution’s result set after identical setup on fresh databases.

  • Best for SELECT, joins, aggregates, ordering, CTEs
  • Setup SQL required
  • Often tagged compatibility: ["dbgrader", "udemy"]

database-state

Learner may submit multiple statements (DDL/DML). After setup + solution (or learner SQL), verification queries run; those results are compared.

Useful verification patterns

PRAGMA table_info(orders); PRAGMA foreign_key_list(orders); SELECT name, type, sql FROM sqlite_schema WHERE name = 'orders'; SELECT COUNT(*) FROM orders;

Prefer PRAGMA / catalog checks over comparing raw CREATE TABLE strings so formatting differences do not fail students.

Database-state exercises are DBGrader-only (compatibility: ["dbgrader"]).

upload-check

Learner uploads a SQLite database file (.sqlite3 / .sqlite / .db, max 3M). The browser opens it with SQLite WASM (no server upload of the DB contents for grading).

  • Author builds an expected reference DB with setup (and optional solution) SQL
  • The same verification_sql runs on the gold DB and on the uploaded file
  • Results are compared (prefer COUNT(*) / filtered checks over volatile id dumps)
  • Built-in example: PollsExercise (Polls batch load)

Upload-check exercises are DBGrader-only (compatibility: ["dbgrader"]).

Exercise JSON and lessons.json

Stored in lti_link.json. Core shape:

{ "version": 1, "type": "sqlite", "mode": "query", "title": "...", "prompt": "...", "instructions_url": "https://www.dj4e.com/assn/dj4e_batch.md", "setup_sql": "...", "solution_sql": "...", "starter_sql": "...", "verification_sql": [], "comparison": { "column_names": true, "column_order": true, "row_order": true, "numeric_tolerance": 0 }, "dialect": "sqlite", "compatibility": ["dbgrader", "udemy"] }

instructions_url is optional. When set to an http(s) URL, learners see an Assignment instructions link under the prompt.

Built-in assignments

Catalog keys live in assignments.php; exercise bodies in assignments/*.php. Built-ins include PantryExercise, SimpleWhereExercise, and PollsExercise (upload-check).

Select under Settings, or set on first launch with LTI custom (copied into the link settings row only when that setting is empty):

"custom": [ { "key": "exercise", "value": "PantryExercise" } ]

Load order: existing lti_link.json wins; else full custom_config JSON; else the built-in named by the exercise setting; else an empty stub.

Preload full exercise from lessons.json

Alternate shape when you are not using a built-in — seeds lti_link.json on first empty launch, or via ?inherit=<resource_link_id>:

"custom": [ { "key": "config", "json": { /* exercise object */ } } ]

Edit → View Assignment JSON → lessons.json custom produces the exercise key snippet when a built-in is selected, otherwise the full config object.

Grading and Attempts

  • Learner Check Answer grades in the browser, then calls /api/record-attempt.php and, on success, /api/grade-submit.php with 1.0.
  • Alternate correct SQL is fine if results (or verification results) match.
  • comparison controls column names, column order, row order, and numeric tolerance.
  • Exploration commands are rejected for Check Answer.

Trusted browser environment

Learners can inspect delivered exercise data. Use DBGrader for practice and formative work, not as a high-stakes secret exam harness.

Runtime

  • SQLite WASM from $CFG->staticroot/js/sqlite/sqlite-wasm-3530300/jswasm/ (3.53.3)
  • Execution in a Web Worker so slow queries do not freeze the UI
  • Always a fresh :memory: database per Run / Check / preview
